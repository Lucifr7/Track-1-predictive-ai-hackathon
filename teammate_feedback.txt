1. MODEL RESULTS (use these numbers in the slides)

We trained simple decision tree models on 8,000 rows and tested them on
2,000 rows the models had never seen. The test rows contain 68 failures.

  Model          Real cases  Caught  Missed  False alarms  Recall  Precision
  Any failure        68        56      12         3         82%      95%
  Tool wear          10         1       9         1         10%      50%
  Overheating        29        28       1         2         97%      93%
  Power              13        13       0         0        100%     100%
  Overstrain         16        16       0         0        100%     100%

  Recall    = of the real failures, how many we caught.
  Precision = of the alarms we raised, how many were real.

How to say it in the pitch:
- "The model catches about 8 in 10 failures, and about 95% of its alarms
  are real." Say "about 80%", not "82%": with only 68 failures in the
  test set, each one moves the score by 1.5 points.
- Tool wear is the weak spot. In this dataset a worn tool fails at a
  random moment between about 200 and 250 minutes of use, so the model
  cannot tell exactly which run it fails on. For tool wear, our tool
  flags "this tool is in the danger zone, replace it".
- Power and overstrain show 100%, but on only 13 and 16 cases, and the
  data is synthetic with failures generated by fixed formulas. Say "no
  mistakes on the test set". Do not say "100% accurate".

Two findings that would make good slides:
- The accuracy trap. Our first model was 97.3% accurate but caught only
  20 of 68 failures (29%). A model that always says "no failure" scores
  96.6%. This is why we report recall and precision, not accuracy.
- Better clues beat a fancier model. We added three combined readings
  (temperature difference, power, torque x tool wear). Same model, same
  settings: failures caught went from 20 to 56, and false alarms from
  6 to 3.

3. A LIMITATION WE BOTH NEED TO EXPLAIN

The persona says Razif gets the list before machines fail. But each row
in the dataset is a single machine run, with the readings and the
failure recorded together. There is no time order in the data. So the
model recognises dangerous operating conditions from current readings.
It does not forecast failures hours or days ahead.

The story still works if we state the assumption: "this morning's
readings show which machines are operating in a danger zone, so Razif
checks those first." Please do not claim on any slide that we predict
failures a set time in advance.

Also for the limitations slide:
- The dataset is synthetic. Real sensor data would be noisier and the
  scores would be lower.
- All RM figures are our assumptions.
- "CNC milling machine", coolant and radiator fans are our scenario. The
  dataset only gives temperature, speed, torque and tool wear. Please
  check the dataset description on the UCI page to confirm it describes
  a milling machine before that goes on a slide.
